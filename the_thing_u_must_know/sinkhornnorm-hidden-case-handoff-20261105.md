# SinkhornNorm 十个隐藏点优化方案

请基于下面的算子规格和十组代表形状，独立实现、测试并优化 Ascend C SinkhornNorm。每个 case 给出一个可检验的起点。先建立自己的 FP32 正确基线，再根据测量选择或替换方案。以下原型和瓶颈假设均待实测。

## 形状与计算合同

`N=B×S`，`H` 是矩阵边长，`I` 是迭代属性。表中的 H1–H10 是测试标签。每核矩阵数以 40 个有效核为例，按连续均分且小任务最多每矩阵一核估算。实现时从设备和 tiling 参数获取实际核数。

| Case | H | I | N | 归一化次数 | 每活跃核矩阵数 | 优先排查 |
|---|---:|---:|---:|---:|---:|---|
| H1 | 100 | 20 | 768 | 39 | 19–20 | 大矩阵的 UB 流量 |
| H2 | 2 | 2 | 1048576 | 3 | 26214–26215 | GM 带宽和短字段搬排 |
| H3 | 3 | 3 | 21 | 5 | 1 | 单矩阵启动、归约和写回固定开销 |
| H4 | 7 | 12 | 35 | 23 | 1 | 23 步中的短向量依赖 |
| H5 | 9 | 20 | 899 | 39 | 22–23 | 多矩阵的有效向量宽度 |
| H6 | 13 | 2 | 7936 | 3 | 198–199 | 短迭代的中间态和搬排成本 |
| H7 | 56 | 10 | 384 | 19 | 9–10 | 批次利用率和 UB 布局 |
| H8 | 64 | 20 | 160 | 39 | 4 | 对齐尺寸的归约和中间流量 |
| H9 | 15 | 20 | 192 | 39 | 4–5 | 单矩阵内的横向归约依赖 |
| H10 | 23 | 32 | 384 | 63 | 9–10 | 长迭代的半步依赖和发射开销 |

复现起点可取 `eps=1e-6`、seed 42、logits 均匀采样于 `[-2,2]`。H2 用 `B=128,S=8192`，其余先取 `B=1,S=N`。表中是本地代表形状，线上 B/S 拆分、EPS 和分布以实际输入为准。边界测试应改变这些参数。分派按形状、迭代深度、对齐和资源条件构造结构域，覆盖其余合法输入。表中的 case 标签和精确参数组合只用于测试。

输入 `mixes` 为 `[B,S,H(H+2)]` 的连续 FP32 张量，`B∈[1,128]`、`S∈[1,8192]`、`H∈[2,128]`、`I∈[1,32]`。每个 token 按 `[H,H,H²]` 切成三个字段，最后一段按行主序排成矩阵。`pre`、`post` 为 `[B,S,H]`，`comb` 为 `[B,S,H,H]`。全程 FP32，单 kernel 完整写出三个输出，保持输入字节与同输入确定性。Host 负责校验、shape、tiling 和启动。轮数固定，Device 执行完整计算，分派只使用元数据。性能计入同一次完整计算的全部步骤。

下面的 CPU PyTorch 参考可用于生成期望输出。

```python
import torch


def reference(mixes, h, iters, eps=1e-6):
    mixes = mixes.to(device="cpu", dtype=torch.float32)
    pre_logits, post_logits, comb_logits = mixes.split((h, h, h * h), dim=-1)
    pre = pre_logits.sigmoid() + eps
    post = 2.0 * post_logits.sigmoid()
    comb = comb_logits.unflatten(-1, (h, h)).softmax(dim=-1) + eps

    for step in range(2 * iters - 1):
        axis = -2 if step % 2 == 0 else -1
        comb = comb / (comb.sum(dim=axis, keepdim=True) + eps)

    return pre, post, comb
```

### 共用实现约定

- **核内任务编号。** 把 `(b,s)` 展平为 `t=b*S+s`。连续 ND 布局下，输入起点为 `t*(H²+2H)`，两个 gate 输出各为 `t*H`，comb 输出为 `t*H²`。`P` 个核连续均分时，第 `p` 个核处理 `[floor(pN/P), floor((p+1)N/P))`。按实际负载再考虑分批或交错，每个 token 的输出区间保持唯一归属。
- **行 softmax 和填充。** 有效元素先减本行最大值，再做 Exp、求和、除法和 `+eps`。无效列不参与 max，初始化和后续归约时贡献零。对填充 lane 做运算后要保证其贡献仍为零，尤其留意 `+eps` 后以及行列布局切换时。列归一化的统计轴为行轴，最后一步始终是列归一化。
- **因子实现。** 若用固定 `X`，令当前矩阵为 `diag(r)·X·diag(c)`，初始 `r=c=1`。列步计算 `q[j]=Σ_i r[i]·X[i,j]`，再更新 `c[j]=c[j]/(c[j]·q[j]+eps)`。行步计算 `p[i]=Σ_j X[i,j]·c[j]`，再更新 `r[i]=r[i]/(r[i]·p[i]+eps)`。每次只更新一个轴，下一步读它的新值。这里的等式按实数推导，FP32 中因子连乘、乘法结合顺序和倒数替代除法都需要独立做误差检查。
- **资源账本。** 用字节列出原始输入、矩阵主缓冲、转置或重排区、尺度、归约临时区、输出暂存及在途 DMA 缓冲。按同时存活的区域求峰值。有效 I/O 下限是 `8N(H²+2H)` 字节，由一次输入和三路输出组成。设备报告的流量还可能包括重复搬运、对齐和 workspace。

## H1（100 × 100，I=20，N=768）

**首稿用分块矩阵、延后施加上一步缩放。** 从按行优先组织的 8×8 或 16×16 小块开始，每个块维护固定位置。每个半步先用上一轴的缩放向量恢复该步真实输入，同时写回缩放后的块并累加本轴统计量。全轴统计完成后只产出下一根缩放向量。最后一次列缩放融合进输出。对比显式的「算轴和、扫整面除法」，这个版本把一次整面缩放和下一次扫描合成同一次读块。尾块按有效行列掩码处理，软最大值统计排除填充，分母中的 EPS 只对有效轴加入一次。

**先验证整面流量。** 同一初值、同一 tile 先比较两趟和融合两版，数每半步 UB 读写字节及合并部分和所需的操作。一个紧凑 FP32 矩阵 40,000 B，双矩阵或双缓冲时把 padding 和临时区一起计入峰值。若写回仍主导，下一稿可改为固定 `X` 和两根尺度向量，验证节省的写流量能否覆盖加权归约成本。

- **落地顺序。** 先做 8×8 块，边长 100 对应 `13×13` 个块，角块只有 `4×4` 有效。首个列统计从 `X` 直接累加。从下一半步起，每个块读入后按上一轴的因子缩放一次，缩放后的值同时写回块和送入本轴归约。当前轴的所有部分和齐备后才生成下一组因子。最后在写出 GM 时应用最后一组列因子。
- **量化对照。** 在两趟版本中，每个常规半步至少有「统计读一次、更新读一次、更新写一次」三次整面访问。融合稿的稳态目标是一读一写，另计块级部分和、尺度广播和边界整理。以 `I=1/4/20` 比较耗时增量，拆出初始 softmax、最终写出和反复扫描各自的影响。
- **分岔条件。** 若向量乘法及 UB 流量下降但 Task 持平，检查块内归约和部分和合并是否取代了原瓶颈。优先尝试把同轴的多个块按固定顺序累加到同一个统计区，再评估更大的块。用 `H=96/100/104` 对比填充与块尾处理。

## H2（2 × 2，I=2，N=1048576）

**首稿用流式直接公式。** 以连续 token 为大 tile，输入每 token 8 个 FP32。一次连续读入 tile，把两个 gate 对和四个矩阵位置拆成向量。每行两个 logits 用稳定的 `d=exp(-abs(x-y))`，形成 `1/(1+d)` 与 `d/(1+d)`，用向量选择恢复原位置，两侧各自加 EPS。随后对 `2×2` 四个位置显式执行列、行、列三步，分母仍加 EPS。输出分别按 2、2、4 个 FP32 连续合包。先做单缓冲验证，再给读写重叠单独做 A/B。

**先验证字节和拆包成本。** 理论有效 I/O 为 `64 B/token`，本点共 `64 MiB`。用相同 tile 对照连续读后在 UB 拆包与分字段跨步读，记录完整 Task、有效带宽、尾 tile 和多核写回边界。极端差值下专门检查较小概率，保留 `d/(1+d)` 的直接计算。

- **落地顺序。** 把一组 token 的 8 个字段拆成 8 条向量。对 comb 的四条向量 `a,b,c,d`，初始列步用 `(a+c+eps,b+d+eps)`，行步用更新后 `(a+b+eps,c+d+eps)`，末列步再用更新后的两列和。每个分母服务两个元素，首版直接除法。sigmoid 的稳定版本可以共享一个 `exp(-abs(z))` 和向量选择，按符号选择结果。
- **量化对照。** 先改变 tile 宽度并记录实际传输大小，再固定获胜宽度比较单缓冲和双缓冲。每个 gate 每 token 8 B，comb 每 token 16 B。若用 32 B 对齐的整块搬出，核边界优先按 4 个 token 对齐，最后一段单独处理有效字节。
- **分岔条件。** 如果吞吐主要随有效字节数变化，优先收敛到更少的拆包与搬运，保留可重叠的计算。若小 tile 或单缓冲耗时明显偏离，再检查等待和利用率。用能跨 tile 边界的相邻 N 和不同 B/S 拆分验证通用性。

## H3（3 × 3，I=3，N=21）

**首稿用一核一矩阵的固定向量图。** 单次读入 15 个数，在本地组织成三条有效行。按行做 max、Exp、三项和，再用固定索引在九个元素中配对同列或同行的三项。显式写出五个归一化半步。三种输出各一次有效区间写回，门控放在 comb 的独立指令间隙里尝试交错发射。

**先验证小任务固定开销。** 比较一核一矩阵和每核两个矩阵拼宽，保持公式、写回方式一致。测 `N=1/2/21` 和不同 `I`，检查 3、3、9 个元素的非对齐输出及相邻核保护区。若打包开销高，保留更直接的单矩阵图。

- **落地顺序。** 以三条对齐行向量存放 `[m00,m01,m02]`、`[m10,m11,m12]`、`[m20,m21,m22]`。列步把三条向量相加得到三个分母，分别更新三条行向量。行步在每条行向量内取前三项求和。先固定归约的读索引，再把同一布局用于 `I=1` 和 `I=3`，以便定位额外半步的成本。
- **量化对照。** 每个 token 有 60 B 有效输入、60 B 有效输出。记录每个 token 的 GM 命令数、UB 重排数和有无向量到标量的依赖。用一样的算术图比较按输出分别写回与核内合并同一输出的相邻 token。合并后仍按三个独立目标地址写。
- **分岔条件。** 如果单矩阵路径在 `I=1` 和 `I=3` 的差很小，优先缩短输入整理和输出等待。若差随 `I` 明显上升，比较直接除法与一次生成分母倒数再广播，按宽 logits 的误差决定取舍。

## H4（7 × 7，I=12，N=35）

**首稿用一张 `7×8` 的行主序工作面。** 列步直接把七条 8 元素行向量做平衡树相加，再沿行方向使用同一组列因子。行步做七个短行归约并广播，各行计算留在原地。第 8 列始终为填充。每半步使用固定步幅，保留两条独立的部分和到最后一层，减少串行累加深度。最终在 UB 整理出 49 个有效元素后写回。

**先验证每步的向量依赖。** 同一工作面比较树形与串行行向量求和，再比较原地更新和局部轴交换。对 `I=1/12/32` 看耗时斜率。对小 EPS、宽 logits 和 `N` 穿过有效核数的点检查填充与写回。

- **落地顺序。** 列步可用 `(R0+R1)+(R2+R3)` 和 `(R4+R5)+R6` 两个部分和，最后合并后给七列加 EPS。行步做七个 7 项归约，将标量分母广播到同行的七个位置。分母留在向量或 UB 通路里，比较把七个分母放在同一临时向量和分别广播的开销。
- **量化对照。** `7×8` 工作面是 224 B，紧凑 comb 输出是 196 B。单独比较末次列缩放与收紧布局是否能在同一次写出准备中完成。测试 `N=35` 与 `P−1/P/P+1`，分开报告一核一张和第二张出现时的时间。
- **分岔条件。** 若行步归约加广播仍主导，可用一个固定的局部转置把行步也变成向量逐项加和。先用 `I=12/32` 测其开销能否回收，再决定保留哪条路径。

## H5（9 × 9，I=20，N=899）

**首稿把不同矩阵排进向量 lane。** 每组 8 或 16 个 token，采用 `X[row][col][lane]`，每个 lane 独立完成一张矩阵。沿某一轴取九个连续的 lane 向量，用 `3+3+3` 固定分组做加权和。UB 内保留一份 `X`，行、列缩放以向量递推，第一版先用 FP32 除法。对 `X` 与 `Xᵀ` 的访问仅改变固定块的遍历次序。每个位置在最终输出时重建一次。

**先验证合批代价。** 同一递推比较组宽 8、16，统计一次性搬排成本、有效 lane 比例和每半步归约开销。主点每核约 22–23 张，尾组空 lane 必须与有效 lane 隔离。加测相邻 N 和 I，确认收益来自摊薄发射或减少填充，而非碰巧命中某个尾组。

- **落地顺序。** 可用 `((i*9+j)*L+lane)` 作为 `X` 的 UB 索引。先搬排一组，再在九组行坐标上并行做 softmax 所需的比较和加和。九条候选值中每条的 `L` 个 lane 都属于不同矩阵。列作用时固定 `j` 并依次走 `i`，行作用固定 `i` 并走 `j`。尺度 `r[i][lane]`、`c[j][lane]` 直接给对应的加权向量读取。
- **量化对照。** 当 `L=8` 时单组 `X` 约 2.5 KiB，当 `L=16` 时约 5 KiB，尺度和搬排另计。每核 22–23 张时，三组 8 lane 与两组 16 lane 的填充分别约 1–2 与 9–10 个 lane。保持 39 步相同，比较更宽的单条指令能否抵消额外 lane。
- **分岔条件。** 如果 16 lane 的主组快、尾组拖慢，可测试宽组与窄尾组共用同一计算图。若矩阵作用本身收益不大，则优先缩短 GM 到向量布局及最终写出的重排。

## H6（13 × 13，I=2，N=7936）

**首稿保留一份初值和三组统计。** 对每张矩阵保留初始 `X`。列扫得到 `a[j]=1/(Σ_i X[i,j]+eps)`，行扫得到 `b[i]=1/(Σ_j X[i,j]·a[j]+eps)`，再列扫得到 `c[j]=1/(Σ_i X[i,j]·a[j]·b[i]+eps)`。最后按行连续写 `X[i,j]·a[j]·b[i]·c[j]`。可以预计算 `a[j]·c[j]` 省去输出热路径的一次逐元素乘法，单独验证其 FP32 误差。把 13 列局部扩到 16 作为易实现的第一版，先按原矩阵顺序处理。

**先验证省下的写流量值多少。** 对照每半步原地更新的版本，保持批次和初始布局一致。再比较同一数据流的矩阵主序与跨 token 并行。对每核近 199 张，任何因 scratch 增长多出的一波都要计入，比较时同时记录整批和尾批成本。

- **落地顺序。** 每条初始行产生 13 个 `X` 后，同时写入 `X` 和累加第一次列统计。第一组列尺度 `a` 就绪后逐行计算 `b`，再逐行读取 `X`、`a`、`b` 并累加最终列统计。计算 `c` 后直接输出。保留一个仅融合「初值生成与第一次列统计」的控制稿，区分统计复用与因子表达各自贡献。
- **量化对照。** `13×16` FP32 工作面为 832 B/张。批宽设为 `T` 时，主矩阵空间就是 `832T` B，再为输入、三组尺度和非对齐写出分别做账。以每核最多 199 张为例，两批要求 `T≥100`。用可装入 UB 的实际 `T` 验证跨过两批边界时是否改变结论。
- **分岔条件。** 如果因子版少写整面却多了明显的乘法或搬排成本，保留初始统计融合，回到显式三步。若问题只出在输出，优先比较 `a·c` 提前合成与按参考顺序逐项乘，不和布局改动放在同一个 A/B。

## H7（56 × 56，I=10，N=384）

**首稿做固定分段流水。** 每矩阵按 `32+24` 行拆成两个连续片段。列归约让两片独立生成长度 56 的部分和，只合并两根统计向量，再分别更新两片。行归约和更新各自在片内完成。最后一次列缩放直接融合到连续行写回。先用单矩阵验证，再用相同内核交错处理两张矩阵，尝试把后一张读入与前一张的计算或输出重叠。以实际 UB 容量和生存期决定交错深度。

**先验证尾批与同步。** 同一分段算法比较串行与双矩阵交错，用每核约 9–10 张的目标及一波少一张、多一张的控制形状，分别观察最长核和完整 Task。若双份暂存让批次退化或等待增加，保留单矩阵分段，单测部分和合并是否仍有收益。

- **落地顺序。** 先把两个片段都保留在 UB。列步由每片产出 56 项部分和，在长度 56 的向量上合并并加 EPS，两个片段随后应用同一组列分母。行步的分母只需要片内数据。进入下一半步前，该矩阵的两个片段都要完成本步更新。最后一列步读两片求和，更新时直接准备写出。
- **量化对照。** 主矩阵为 `56×56×4=12,544 B`，两张主矩阵约 24.5 KiB。部分和每片 224 B。以双矩阵组为例，每核 9 张对应 `2+2+2+2+1`，10 张对应 `2+2+2+2+2`。可用 `N=8P/9P/10P/11P` 控制尾组，观察 `N=384` 时最长核更接近哪一组。
- **分岔条件。** 如果等待主要在两片列部分和的汇合点，试 `28+28` 或以实际向量块为单位的分割，保持总扫描量一致。若算术差异很小，保留更简单的片段大小，把时间花在上一张写出和下一张搬入的重叠上。

## H8（64 × 64，I=20，N=160）

**首稿用无填充的 8×8 块存固定矩阵。** 每块在同一布局完成两轴作用，`X` 始终为初始矩阵。遍历 8 个块累积每组行或列的加权部分和，归约树直接产出对应的 8 个尺度。行更新为 `r[i]←r[i]/(r[i]·(Xc)[i]+eps)`，列同理用更新后的 `r`，从 `r=c=1` 开始并先做列步。对每个块比较用原始行向量直接累加列和与保留一份局部转置，两者都保持 39 步和固定归约顺序。最终才重建输出。

**先验证同一布局的两轴成本。** 主点约每核四张，先保持单矩阵方案与相同的多核划分，仅变更块内归约，观察两个轴各自读写量、临时空间和完整 Task。wide 输入要检查尺度连乘的动态范围。若局部转置成本能摊平，再测跨矩阵交错，避免把两个变化算成一个收益。

- **落地顺序。** 将 `X` 存成 `X[block_row][block_col][local_row][local_col]`。列步在每个 8×8 块里，用 `r` 的 8 个标量乘对应行，再逐列相加得 8 个部分和。同一列块的八个行块合并。行步使用 `c` 的八项加权，同一行块的八个列块合并。最后按行把块内结果按列块次序拼成 64 个连续元素写出。
- **量化对照。** 主矩阵 16 KiB，第二种块内方向再占 16 KiB，两根尺度共 512 B。对照 A 每半步按同一工作面读取，B 在初值阶段一次性写两个方向、每半步只读对应方向。分别测 `I=1/10/20`，判断第二份布局的准备成本何时摊平。
- **分岔条件。** 若两个方向的归约差异小，保留单副本以给多矩阵调度留空间。若一轴明显较慢，可只为该轴改块内表示。强对角、强单列和置换 logits 用于检查因子在很尖锐的矩阵上是否稳定。

## H9（15 × 15，I=20，N=192）

**首稿把空间并行用在单矩阵内部。** 将矩阵放进 `16×16` 工作面，每行或列拆成四段，每段最多四项。归约把四个短段分别求和，再两两合并，行与列都保持固定寻址。先用原地的显式归一化，让计算图只依赖矩阵和长度 15 的临时分母。若整面更新主导，再测试只保留分母和固定 `X` 的尺度版，复用同一棵归约树。

**先验证归约依赖。** 一核串行处理分到的 4–5 张，对照相同布局下逐项累加和分段树，再试两张交错。使用 `I=1/20/32` 区分布局成本和每半步节省。第 16 行和列要排除在 softmax 最大值和有效输出之外，并在归约中贡献零。

- **落地顺序。** 固定分组为 `[0..3]`、`[4..7]`、`[8..11]`、`[12..14]`，每个部分和最多四项。列步从四段行同时形成四根列向量，最后两两合并。行步可先对行内四段求和，再把各行分母集中写入连续向量。用固定合并顺序保持复现。
- **量化对照。** 每张工作面 1 KiB，一核五张只需 5 KiB 主矩阵。先验证把多个 token 一起读入、逐张执行的控制稿，再测真正两张交错。分别报告读写批次和计算批次，避免把少发几次 DMA 当成归约提速。
- **分岔条件。** 若短段树更快但整面更新仍吞掉收益，替换为共用约定里的固定 `X`，沿相同短段计算加权和。若行内收集步骤太重，比较一开始就把每个四项段对齐放置，避开每半步重新整理。

## H10（23 × 23，I=32，N=384）

**首稿做固定两矩阵交错的因子递推。** 单矩阵先做 `8+8+7` 三段固定加权归约，段间只合并长度 23 的结果。每半步严格用上一半步已经完成的尺度。两张矩阵的状态彼此独立，可在 A 的除法或归约依赖等待期间发射 B 的加权部分和。先验证单矩阵再加入交错，同一矩阵依旧完成 63 步。尾部一张时使用同一条单矩阵计算路径。

**先验证发射与依赖等待。** 比较单矩阵串行、双矩阵串行和双矩阵交错三个版本，固定布局和归约树，避免把批量和交错混在一起。对 `I=2/16/32` 看耗时随步数的变化。若交错增加了读写竞争，先减少跨指令存活的部分和，再判断可隐藏多少等待。

- **落地顺序。** `23×24` 行主序是易实现的起点，最后一列为零。把矩阵作用的收缩轴切成 `8+8+7`，段内产生部分和，最后合并为 23 项。以列步为例，在 A 的部分和就绪后发出 A 的尺度更新，再发 B 的列部分和。A 的后继行作用等 A 的新列尺度可用，B 的依赖同样独立。先画出两张矩阵的读写依赖，再按目标 SDK 支持的同步方式实现。
- **量化对照。** 每张固定矩阵约 2.16 KiB，一轴的三段部分和为 276 B。每轮若把所有部分和写入再读回，两张、两个轴会放大临时区流量。比较「三段全部暂存」与「固定次序边产出边合并」，对照设备上的等待比例、向量发射数和完整 Task 随 `I` 的斜率。
- **分岔条件。** 若两张交错使每半步斜率下降，尝试用相同布局处理 `9=4×2+1` 和 `10=5×2` 的尾差。若没有减少等待，保留单矩阵版，把三段合并下沉到加权归约的末级。用 `I=1/2` 先定位方向和 EPS，再用 `I=32` 检查长轨迹误差。

## 接手后怎么测

1. 为本点选自己可复现的正确基线，标记候选源码、实际入口、构建、核数、UB 峰值与分批方式。用上面的 CPU 参考计算期望输出。按目标 CANN 版本核对搬运对齐、非对齐 API、向量 mask、填充与尾地址。非对齐写回要保证有效区间和不同核的写入互不踩踏。 [昇腾官方非对齐处理指南](https://www.hiascend.com/developer/techArticles/20250627-1)
2. 对三个完整输出逐元素检查绝对与相对误差均 `<1e-4`，并检查输入不变和同输入复现。至少补宽范围 logits、常数或近常数、第二个 seed、相邻任务量以及不同的正 EPS。将这些分布和 EPS 写成测试参数。因子版对照各半步状态定位溢出或误差漂移，重点看分母 `+eps`、初值 `+eps`、padding 与最后一步。
3. 性能用同设备、同输入、同构建选项交替跑完整 Task A/B。先只改一个可解释的变量，记录中位数、波动以及改动触及的邻近输入。小算子优先验证计时噪声和写回，长迭代用不同 `I` 分离固定成本与每半步成本。局部 profile 用于解释完整 Task 的结果。
4. 合并前，用同一整版重跑十组代表形状和受影响的边界，包括 `I=1`、短任务、批次尾部和不同 B/S 拆分。按 case 汇报实际入口、最大误差、完整 Task 中位数及波动。把实测结果与尚待验证的设计假设分开。

### 第一批实验与交付格式

可以先选 H2、H3、H6、H10 各做一组对照。四点分别覆盖流式带宽、极短任务、三半步搬排和长迭代依赖，得到的量测方法可以带到其余各点。每组先跑 uniform 和宽 logits 的正确性，再跑同一输入的交替 A/B。计时差落在重复运行波动里时，保持同一构建并增加交替轮数，报告可区分的结果和仍未区分的结果。

宽 logits 可先用 `[-12,12]` 均匀输入，再用带尖峰的矩阵测试极端归一化。试 `eps=1e-8/1e-6/1e-3`，这些值作为本地测试点。用同一个 `N` 改 `B/S` 验证展平索引，用不同 `N` 穿过核数和批宽边界验证尾部。针对重排密集的版本，可对同一输入独立置换矩阵的行和列，按相应置换核对 comb 输出，以暴露行列轴或回写索引错误。
